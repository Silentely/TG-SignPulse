# JEV 语义决策引擎

TG-SignPulse 内置了专门面向 Telegram 机器人交互场景的原生语义决策引擎 —— **JEV**（采用 SystemOne 语义决策协议）。

它解决了传统脚本和打卡工具在面对 Telegram Bot 频繁修改按钮文案、Emoji 变化或多语言微调时的脆弱性，为任务编排提供了高鲁棒性的智能匹配能力。

---

## 为什么需要 JEV？

在长期的 Telegram 自动化签到与交互中，最大的痛点在于**规则容易失效**：
- 机器人的内联按钮（Inline Keyboard）今天叫 `每日签到`，明天可能变成了 `🎁 签到领金币`，后天又改版成 `Daily Check-in`。
- 如果仅靠固定的子串匹配或手工编写复杂的正则表达式，哪怕文案只多了一个空格或 Emoji，打卡任务就会因为“未找到匹配按钮”而宣告失败。
- 但如果每个按钮都调用一次通用大语言模型（如 GPT-4o），又会带来高延迟、高成本以及大模型幻觉带来的超时或不确定性。

**JEV 专为这一场景而生**：它通过紧凑的语义上下文评估当前消息文本与所有候选内联按钮的语义关联，在毫秒级延迟下给出高置信度的决策选择，并在服务异常时提供自动降级保护。

---

## JEV 与通用 AI（OpenAI）的区别与互补

很多用户容易混淆设置中的「AI 设置」与「JEV 设置」，二者在 TG-SignPulse 中各司其职、协同工作：

| 维度 | JEV 语义决策引擎 | 通用 AI 动作（OpenAI 兼容） |
| :--- | :--- | :--- |
| **主要定位** | Telegram 按钮语义推断、动态路由、规则自愈 | 多模态 OCR 视觉、算术解题、诗词验证码生成 |
| **典型场景** | 从 10 个按钮中智能识别出“签到”、“抽奖”或对应题目的答案按钮 | 识别图片里的变形字母/算术公式/物体单选 |
| **执行延迟** | 毫秒级（极快），支持高频本地语义缓存 | 秒级（取决于上游 LLM 与图像传输耗时） |
| **故障保护** | **三态熔断器（Circuit Breaker）**，异常时自动降级到规则匹配 | 备用节点重试与故障转移机制（Fallback Nodes） |
| **自愈进化** | **智能规则建议（Suggestions）**，反哺更新任务配置 | 单次即用即抛，不主动修改任务定义 |
| **配置文件** | `.signer/.jev_config.json` | `.openai_config.json` |

> [!TIP]
> **最佳实践**：同时启用 JEV 与通用 AI 动作。当机器人发送带图算术题时，AI 动作负责从图像中计算出答案数字；JEV 则负责在机器人的打卡键盘上精准命中语义匹配的按钮。

## 核心机制

### 1. 三态熔断器（Circuit Breaker）

为了保障自动化无人值守系统的绝对稳定性，JEV 引擎内置了工业级的三态熔断器：

```text
       ┌───────────连续失败达到阈值──────────┐
       ▼                                     │
   [ CLOSED ] ──正常流量──► (调用成功重置)    │
   (正常决策)                                │
       ▲                                     ▼
       │                                  [ OPEN ]
   (探测成功)                            (快速熔断降级)
       │                                     │
       └───────────冷却超时进入半开──────────┘
                  [ HALF_OPEN ]
```

- **正常运行（Closed）**：全部语义决策请求正常执行，本地缓存命中时直接内存返回，不消耗网络请求。
- **熔断开启（Open）**：当网络抖动、上游 API 故障或凭据异常导致连续失败达到阈值时，熔断器立即被绊开（Tripped）。此时系统**不再向上游发起网络调用**，而是零延迟无缝降级为**纯规则/正则表达式模式**继续执行任务，绝不阻塞打卡主流程。
- **半开探测（Half-Open）**：冷却周期过后，系统允许少量探测流量尝试恢复，若确认服务健康则自动复位回 Closed 状态。

### 2. 仪表盘全景可观测

在 TG-SignPulse 的控制台大盘上，你可以随时掌握 JEV 的健康状态：

- **顶栏状态徽章**：
  - 🟢 `JEV 正常 (命中率 85%)`：引擎健康运行，同时显示本地缓存命中率。
  - 🟠 `JEV 熔断降级中`：熔断器触发，提醒用户当前正处于安全降级保护模式。
  - ⚪ `JEV 未启用`：未配置或已在设置中关闭。
- **熔断告警横幅**：一旦进入熔断，首页大盘顶部会呈现清晰的高亮告警条，展示具体的错误原因与自动恢复倒计时。

## 智能规则建议与自愈（Rule Suggestions）

JEV 不仅仅是一个决策执行器，还具备**自适应规则沉淀**能力：

### 工作流原理

1. **观察与沉淀（Observations）**：每次执行签到或按钮交互时，如果出现置信度波动、按钮文本发生显著偏移或降级执行，JEV 会将上下文数据结构化记录在后台观察库中。
2. **生成规则建议（Suggestions）**：引擎分析近期收集到的成功与失败模式，自动推断出更优的按钮正则表达式或关键词规则。
3. **人工审核与一键应用（Review & Apply）**：
   - 在 **运行日志（Logs）详情弹窗** 中，如果有针对该任务的优化建议，会直接唤出建议面板。
   - 面板展示**修改原因**、**新旧规则 Diff 对比**以及关联的观测事件。
   - 点击 **「采纳建议」**，系统会自动以安全热更新方式修改对应任务的动作配置并递增版本号；如果不希望调整，可点击 **「忽略」**。

### 配置项说明

| 字段 | 默认值 | 说明 |
| :--- | :--- | :--- |
| **启用 JEV** | 关闭 (`false`) | 是否在任务执行中启用语义决策与建议收集 |
| **运行模式** | 官方模式 (`official`) | 可选 `official`（官方托管服务）或 `custom`（自定义端点） |
| **API Base URL** | `https://api.typesafe.ai/v1` | 语义服务的基础请求地址 |
| **模型名称** | `jev-1.13.0` | 语义决策模型代号 |
| **API Key** | 空 | 访问凭据（保存后自动掩码脱敏，防止前端明文泄露） |
| **超时时间** | `10.0` 秒 | 单次决策请求的最大允许超时 |

### 连通性测试

在表单中填写配置后，点击 **「测试连接」** 按钮：
- 系统会发起一次沙箱 PING/PONG 决策判定请求。
- 返回耗时（毫秒）、决策结果与状态码。测试通过后即可放心点击保存。

### 安全机制

- **SSRF 阻断保护**：JEV 客户端内置私有 IP 与危险主机名校验，杜绝内网穿透与地址欺骗攻击。
- **凭据外送隔离**：修改 `Base URL` 时必须同时显式输入 `API Key`，系统严格禁止将已保存的密钥发送给未经信任的新域名。
