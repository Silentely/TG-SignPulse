# 备份与恢复（WebDAV / 对象存储）

本指南面向面板使用者：如何配置 WebDAV 或对象存储（S3 / Cloudflare R2 / MinIO / 阿里云 OSS）、设定备份目标策略、手动与自动备份、从远端下载，以及换机恢复。

技术细节与 API 见 [运维手册](/reference/ops)。

## 两种备份的定位与区别

| | 配置 JSON | 完整备份（WebDAV / 对象存储） |
|--|-----------|---------------------------|
| 入口 | **设置** → **数据管理** → **导出配置 JSON** | **设置** → **数据管理** → **完整备份** |
| 任务配置 | ✅ | ✅（打包在 `.signer` 目录） |
| 登录会话 `sessions/` | ❌ | ✅ |
| 数据库 `db.sqlite` | ❌ | ✅（SQLite 部署环境） |
| 面板一键导入 | ✅ | ❌（需停止服务后解压覆盖） |
| 敏感密钥 | 导出时自动脱敏；导入不覆盖服务器已有密钥 | 随文件原样打包，请妥善保管 |

- **仅迁移任务流程与系统参数** → 使用配置 JSON  
- **整机迁移 / 灾难恢复** → 使用完整备份（本页指南）

完整备份**不含** `.admin_bootstrap_password`（避免初始密码随备份文件外泄）。

## 1. 准备 WebDAV

任意支持 WebDAV 协议的网盘或服务端均可，例如 Nextcloud、ownCloud、Alist 或部分 NAS。

在面板填写的 **WebDAV URL** 一般为「用户文件根路径」，常见示例：

```text
https://cloud.example.com/remote.php/dav/files/<你的用户名>
```

| 字段 | 说明 |
|------|------|
| WebDAV URL | 须以 `http://` 或 `https://` 开头 |
| 用户名 | WebDAV 登录账号 |
| 密码 | 首次配置时必填；之后留空表示「保持已保存密码不变」 |
| 远端目录 | 相对路径，默认 `tg-signpulse-backups`；支持多级子目录如 `backups/tg` |

> 密码与 Bot Token 在设置页 **不会回显明文**（仅提示「已保存」）。换浏览器或清理缓存后重新打开设置，密码框为空属于正常安全行为。

## 2. 准备对象存储（S3 / R2 / MinIO / OSS）

支持任意兼容 S3 协议的对象存储服务。面板已内置主流服务商快速预设：Cloudflare R2、AWS S3、MinIO、阿里云 OSS。

| 字段 | 说明 |
|------|------|
| Endpoint URL | 形如 `https://s3.us-east-1.amazonaws.com` 或 `https://minio.example.com:9000`；Cloudflare R2 为 `https://<account>.r2.cloudflarestorage.com` |
| 存储桶 | Bucket 名称 |
| Access Key | 访问密钥 ID |
| Secret Key | 首次配置时必填；之后留空表示「保持已保存密钥不变」 |
| 区域 | 默认 `auto`；Cloudflare R2 保持 `auto`，MinIO / AWS / OSS 按服务端实际地域填写 |
| 前缀 | 对象键前缀，默认 `tg-signpulse-backups` |
| 代理 | 可选，走 HTTP/SOCKS 代理访问对象存储端点 |
| 启用开关 | 打开后才视为已配置；关闭时对象存储不参与备份 |

> Endpoint 必须带协议头（`https://` 或 `http://`）；使用 MinIO 自签证书时需确保面板服务端容器或宿主机信任该证书。

## 3. 备份目标策略（backup_target）

系统支持通过 **备份目标策略** 灵活选择上传落点：

| 策略选项 | 标识值 | 行为说明 |
|----------|--------|----------|
| **智能选择 (默认)** | `auto` | 若配置了 WebDAV 优先上传 WebDAV；未配置 WebDAV 且启用了对象存储时上传对象存储；两者均未配置则回退为浏览器下载 |
| **仅 WebDAV** | `webdav` | 仅上传至 WebDAV 服务端；若 WebDAV 未配置则明确拦截并报错 |
| **仅对象存储** | `s3` | 仅上传至 S3 兼容对象存储；若对象存储未启用或凭据未配置完整则明确拦截并报错 |
| **双端同时备份** | `both` | 每次备份同时上传至 WebDAV 与对象存储；**两端均上传成功后才删除本地副本**；若任一端失败，本地副本保留作为容灾兜底，并发送多端告警 |

## 4. 面板配置操作

进入面板 **设置** → **数据管理**，区域划分为三个清晰标签页：

1. **远端存储配置**：
   - 切换 **WebDAV** 与 **对象存储** 子卡片，分别填写连接凭据与存储目录/桶信息。
   - 对象存储支持点击预设按钮一键填入主流服务商模板。
   - 填写后点击 **测试连接**，验证凭据有效性与网络连通性。
2. **自动备份策略**：
   - 打开 **自动备份** 开关。
   - 选择 **备份目标**（智能选择、仅 WebDAV、仅对象存储、双端备份）。
   - 设置 **执行间隔**（小时，1–168）与 **保留份数**（本地与远端保留的快照数，默认 3，最大 30）。
   - 点击 **保存备份设置**。
3. **数据迁移与归档**：
   - 导出与导入系统配置 JSON。
   - 点击 **灾难恢复指引** 查看标准恢复操作命令。

> 点 **上传备份**、**测试连接** 或 **列出远端备份** 时，面板会**自动先保存当前表单配置**再发起服务端请求，避免表单未保存导致依然使用旧配置。

## 5. 手动上传备份

1. 确认 WebDAV 或对象存储连接配置已填写且测试通过。
2. 根据策略或实际需要，点击 **上传备份到 WebDAV** 或 **上传备份到对象存储**。
3. 上传成功后界面会提示落点（远端文件名及大小）。

服务端会将数据目录的关键路径（SQLite 数据库、Telegram 会话目录、`.signer` 任务配置、全局及 AI 配置等）打包为 `tg-signpulse-backup-YYYYMMDD-HHMMSS.tar.gz` 后上传到指定远端。

## 6. 自动备份工作机制

在自动备份策略中开启定时备份后，调度器会在后台周期性执行任务：

1. 到点后自动打包生成 `auto-YYYYMMDD-HHMMSS.tar.gz`。
2. **单端上传场景（`webdav` / `s3` / `auto`）**：
   - 上传成功 → **删除本地该副本**（节省服务器磁盘空间），并按保留份数清理远端更旧的备份文件。
   - 上传失败 → **保留本地文件** 便于手动补传，并触发 Telegram Bot 失败告警。
3. **双端备份场景（`both`）**：
   - 调度器并发或依次推送到 WebDAV 与对象存储。
   - **双端全部成功** → 删除本地副本，双端分别执行旧包轮转清理。
   - **任一端失败** → 本地副本严格保留，通知中合并输出具体失败端及错误详情。
4. **未配置任何远端**：仅在本地 `data/backups/` 目录下按保留份数轮转。

### 备份失败通知

触发备份失败通知需同时满足：

- **系统设置** 中 **Telegram Bot 通知总开关** 已开启；
- 已配置有效的 Bot Token 与 Chat ID。

> 备份失败通知与「任务失败通知」相互独立：关闭签到任务失败通知**不会**影响备份失败通知的发送。静默时段内通知会自动跳过。

---

## 7. 列出与下载远端备份

1. 在 **远端存储配置** 页面点击 **列出 WebDAV 备份** 或 **列出对象存储备份**。
2. 表格展示远端目录中的 `.tar.gz` 文件（文件名、大小、最后修改时间）。
3. 点击某一行的 **下载** 按钮，文件会通过流式传输下载到本地浏览器。

> 下载文件仅用于获取备份归档，**不会**在面板内自动覆写或恢复当前数据。

## 8. 灾难恢复指南

为避免在线覆盖正在运行的 SQLite 数据库与 Telegram 连接会话导致数据损坏，面板**不执行在线热恢复**。

你可以直接在面板「设置 → 数据管理 → 数据迁移与归档」中点击 **灾难恢复指引** 弹窗复制针对 Docker 或宿主机环境的标准命令。

### 标准恢复步骤

1. **获取备份包**：从面板下载远端备份文件，或直接从网盘/对象存储桶中获取 `auto-*.tar.gz` 或 `tg-signpulse-backup-*.tar.gz`。
2. **停止服务**：
   ```bash
   # Docker Compose 部署：
   docker compose stop app
   # 或 docker run 部署：
   docker stop tg-signpulse
   ```
3. **定位数据目录**：
   Docker Compose 部署默认挂载宿主机的 `./data` 目录到容器内 `/data`。
4. **解压覆盖数据**：
   ```bash
   # 将备份包解压覆盖到宿主机的数据目录 ./data
   tar -xzf tg-signpulse-backup-YYYYMMDD-HHMMSS.tar.gz -C ./data
   ```
5. **确认权限并启动**：
   确保数据目录读写权限正确后启动容器：
   ```bash
   docker compose start app
   ```
6. **验证状态**：打开面板检查账号列表与任务列表。如个别账号会话失效，按提示重新登录。

### PostgreSQL 部署说明

若配置了 `APP_DATABASE_URL` 使用外部 PostgreSQL 数据库：

- 备份包内的 `db.sqlite` 不包含 PostgreSQL 中的业务表数据；
- 数据库请通过 `pg_dump` 或云厂商快照独立备份恢复；
- `sessions/` 登录会话与 `.signer` 任务配置仍须从完整备份包中恢复。

## 9. 最佳实践建议

| 建议项 | 实践说明 |
|--------|----------|
| 先测试再开启自动备份 | 避免凭据填写错误导致定时备份持续静默失败 |
| 保留份数建议 ≥ 3 | 为意外损坏或误操作预留足够的回滚周期 |
| 推荐双端异地容灾 | 核心生产环境建议选择 `both` 目标，同时备份至本地 NAS WebDAV 与云端 S3 对象存储 |
| 备份文件妥善加密 | 完整备份包含 Telegram 会话凭据与任务密钥，等同于账号控制权，切勿公开 |

## 10. 常见问题

### 为什么设置中的密码框显示为空？

出于安全合规要求，服务端不会向前端回传已保存的 WebDAV 密码与对象存储 Secret Key。输入框占位符提示「已保存」即表示后台已持久化凭据；需要变更时直接输入新密码保存即可。

### 测试连接成功但上传备份失败？

- 检查账号在远端路径是否具备写入和创建目录的权限；
- 检查对象存储 Bucket 权限策略是否允许 `s3:PutObject`；
- 检查网络代理或网关反向代理是否对大文件上传限制了请求体大小（如 Nginx 的 `client_max_body_size`）。

### 自动备份没有在远端生成文件？

- 确认 **自动备份** 开关已勾选并点击了 **保存备份设置**；
- 检查远端配置是否完整有效；
- 检查本地 `data/backups/` 目录下是否保留了 `auto-*.tar.gz`（上传失败时会自动保留）；
- 查看面板日志或 Telegram Bot 是否收到告警通知。
