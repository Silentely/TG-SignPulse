# AI 动作

## AI 在 TG-SignPulse 中做什么

AI 主要负责解决机器人交互里“无法直接靠固定文本匹配”的步骤，例如：

- 图片验证码
- 诗句填空
- OCR 识别
- 基础算术计算题
- 根据题面推断要点击哪个按钮

## 启用前提

在系统设置里配置 AI：

- 选择 AI 提供商：**OpenAI 兼容端点** 或 **Cloudflare Workers AI**
- `API Key` / Cloudflare Workers AI `API Token`
- `Base URL`（仅 OpenAI 兼容端点，可选）
- `Model`（可选；不填写时使用所选提供商的默认模型）

这些设置会保存到数据目录下的 `.openai_config.json`。

### 服务商与协议支持

系统支持两大类 AI 服务后端：

1. **OpenAI 兼容接口**：支持 OpenAI 官方及各类兼容网关（如 Azure OpenAI、DeepSeek、OneAPI 等）。
2. **Cloudflare Workers AI**：原生适配 Cloudflare 视觉模型：
   - **Cloudflare 账户 ID**：填写控制台中的 32 位十六进制 Account ID。
   - **Model**：默认使用 `@cf/meta/llama-3.2-11b-vision-instruct`，也可以手动填写其他 `@cf/` 模型名。
   - **API Token**：填写具备 Workers AI 权限的 Cloudflare API Token。请求会以 Bearer Token 方式发送。
   - **Base URL**：不需要手填。系统会根据 Account ID 自动拼接 `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai`，避免把 Token 发到错误端点。
   - **首次使用授权**：Cloudflare 部分模型（包括 Llama 3.2 Vision）首次调用前需要接受模型许可协议。保存配置后，点击「测试 AI 连接」，系统会自动提交一次 `agree` 完成授权，再重试连接请求。
   - 系统会自动调用 Cloudflare REST 接口，直接传递图像二进制数据并解析结构化答案。在面板「系统设置」中点击「测试 AI 连接」可直接检验连通性。

OpenAI 兼容端点默认使用 `gpt-5-nano`。需要使用其他模型时，直接在 **Model** 字段填写模型名；需要使用兼容网关时，在 **Base URL** 填写该服务的公开 HTTPS 地址。

## 备用节点（故障转移）

主节点请求失败后会自动按顺序尝试「备用 AI 节点」，提升 AI 动作在网络抖动、
限流或单个服务不可用时的可用性。在系统设置的 AI 区块「备用 AI 节点（故障转移）」
中可添加多个节点，每个节点包含：

- `Base URL`
- `Model`
- `API Key`（留空表示沿用已保存的密钥，不修改）

两个易混淆的行为：

- 主节点会走完整的参数兼容降级（如自动去掉 `response_format` / `temperature`），
  之后才转备用节点；备用节点按「严格 → 保守」依次尝试。
- 备用节点中任一节点因密钥/模型配置错误失败时，不会中断对其余备用节点的尝试。

服务端也可用环境变量配置，值为 JSON 数组，例如：

```text
OPENAI_FALLBACK_PROVIDERS='[{"base_url":"https://backup.example.com/v1","api_key":"sk-xxx","model":"gpt-5-nano"}]'
```

环境变量优先级高于 `.openai_config.json`。

## 默认模型

不同 AI 提供商使用不同的默认模型：

- OpenAI 兼容端点：

```text
gpt-5-nano
```

- Cloudflare Workers AI：

```text
@cf/meta/llama-3.2-11b-vision-instruct
```

如果你在设置里指定了别的模型，系统会优先使用你填写的模型。

## 视觉模型的语言选择

选择视觉模型时，优先让模型的强项语言与签到 Bot 的题面语言一致。

视觉模型对训练语种比较敏感：图片里的文字、按钮文案、题面说明都属于模型要「读」的内容。题面语言与模型的主语言一致时，字符识别和语义判断更稳，响应也更快。

- **Bot 提供英文界面**（英文按钮、英文图片题、英文提示文案）：选择以英文为主的视觉模型，例如 `gpt-5-nano`、`gpt-4o`、Claude 系列，或 Cloudflare 的 `@cf/meta/llama-3.2-11b-vision-instruct`。内置的图片选择、按钮验证和 OCR 提示词均为英文，与英文题面匹配；内置计算题提示词是中文，需要统一语种时可用自定义 `ai_prompt` 覆盖为英文。
- **Bot 提供中文界面**（中文按钮、中文诗词填空、中文计算题）：选择中文优化的多模态模型，例如 Qwen-VL、GLM-4V、商汤 SenseNova 等。
- **题面中英混排**：以主要题面语言为准；难以判断时选多语言能力均衡的模型。

Cloudflare Workers AI 的 Llama 3.2 Vision 以英文为主：系统会把中文选项自动翻译成英文再送给模型，这里有一层翻译延迟和译文误差。Bot 本身就是英文时，这一步可以直接跳过，识别链路更短。

自定义 `ai_prompt` 时也建议沿用题面语言：英文题面配英文提示词，中文题面配中文提示词。

## 支持的 AI 动作

| 动作 | 用途 |
| --- | --- |
| 根据图片选择选项 | 识别题面和候选选项，返回应该点击的按钮 |
| 回复计算题 | 读题后直接发送答案文本 |
| AI 识图后回复文本 | OCR 或视觉识别后把结果发出去 |
| AI 计算后点击按钮 | 先算出结果，再匹配同名按钮点击 |

## 自定义提示词

当前前端已经支持在 AI 动作编辑框中填写自定义提示词。

规则：

- 字段名是 `ai_prompt`
- 留空则使用内置默认提示词
- 填写后只对当前这一步生效
- 关键词监听里的后续 AI 动作也支持这个能力

适合的自定义方式：

- 强调“只返回按钮文字”
- 强调“忽略图片上的 logo、水印、装饰元素”
- 强调“这是诗词填空，不是 OCR 原样抄写”
- 强调“只输出最终答案，不要解释”

## 当前默认提示词行为

系统内置了四类默认 system prompt。

### 1. 图片单选

用于“根据图片和题目，从选项里选一个答案”的场景。

默认要求模型：

- 理解图片和题面
- 选择唯一最合理的选项
- 返回 JSON

返回格式：

```json
{"option":1,"reason":"short reason"}
```

### 2. 图片/按钮验证

用于“根据图片、消息文本和按钮列表，决定要点哪些按钮以及顺序”的场景。

默认要求模型：

- 同时理解图片、caption、按钮文本
- 支持诗句填空、短语补全、图片问答、数学结果
- 返回按钮索引列表

返回格式：

```json
{"options":[1], "reason":"short reason"}
```

### 3. OCR 文本提取

用于“从图片里提取最相关文本并直接回复”的场景。

默认要求模型：

- 返回纯文本
- 不要 Markdown
- 不要解释

### 4. 计算题回答

用于“根据题目算出结果再回复”或“算出结果后去点击同名按钮”的场景。

默认要求模型：

- 只给出答案
- 不要解释
- 不输出额外内容

## 什么时候应该写自定义提示词

建议在这些场景下自定义：

- 机器人题面不是普通 OCR，而是语义题
- 按钮里有大量干扰项
- 你希望强制返回“按钮文字”或“编号”
- 题目经常是诗词、成语、谚语、顺序类任务

## 常见用法

### 识图后点击按钮

适合：

- “请完成诗句填空”
- “根据图片选出正确答案”
- “根据图中内容点击对应按钮”

推荐做法：

1. 前一步先点击触发验证
2. 下一步立即放一个 AI 点击类动作
3. 如有必要，为这一步填写自定义提示词

### OCR 后回文本

适合：

- 图片里直接有验证码文字
- 机器人要求把图上的内容发回去

### 计算后点按钮

适合：

- 按钮本身就是答案选项
- 机器人不是要你发文本，而是要点对应答案按钮

## 调试建议

- AI 动作失败时先检查 `.openai_config.json` 是否正确
- 在设置里先测试 AI 连接
- 观察任务流程日志，看 AI 动作是“没有拿到候选按钮”还是“拿到结果后没有匹配到按钮”
- 如果默认提示词效果一般，给该动作补一个更明确的 `ai_prompt`


## Jev 语义自动化策略

除了基于 OpenAI 协议的传统视觉/文本验证码外，TG-SignPulse 还引入了针对签到自动化场景的 **Jev 语义自动化** 体系：

### 核心能力
1. **语义结果复核 (Result Assist)**：在显式文本/正则规则未匹配时，由大模型根据任务目标进行置信度判别，协助确认签到奖励是否已到账。
2. **安全候选按钮选择 (Button Candidate Selection)**：单目标精确文本未命中时，在过滤支付、提现、充值等敏感操作后提取安全候选按钮，基于 SHA-256 消息指纹进行防篡改点击。
3. **异常分流策略 (Triage Disposition)**：已提供异常分类请求与处置判定函数，硬异常保持原处置；当前尚未接入生产执行调用链，不能依靠 `semantic_triage` 自动分流异常。
4. **规则建议审阅 (Suggestions)**：支持审阅、忽略和应用已存储的字面规则补丁，应用时检查任务配置版本，冲突返回 HTTP 409。当前规则变化候选聚合与补丁构建函数尚未接入生产调用链，开启 `drift_enabled` 不会自动生成建议。

### 配置说明
- **配置入口**：进入 **系统设置** → **JEV / 语义接口**，选择官方或自定义接口，填写密钥后保存；**测试连接** 会先保存当前表单。
- **配置文件**：独立保存于签到引擎工作目录下的 `.jev_config.json`（默认 `/data/.signer/.jev_config.json`；可通过 `APP_SIGNER_WORKDIR` 更改工作目录），与传统 OpenAI 配置完全解耦。
- **接口配置**：官方接口默认 `base_url=https://api.typesafe.ai/v1`、`model=jev-1.13.0`；自定义接口需支持 Jev System One 协议。更换接口主机时请重新填写密钥，否则已保存的密钥会被清空。
- **资源预算**：`enabled` 默认 `false`；`timeout_seconds` 默认 `8`（1–30 秒），`max_concurrency` 默认 `2`（1–5），`max_calls_per_run` 默认 `6`（0–30），`max_calls_per_minute` 默认 `60`（0–600）。两种调用次数预算设为 `0` 表示不限制对应次数。
- **任务策略**：全局启用后，仍需在任务配置中启用对应的 `semantic_result` 或 `semantic_button` 策略，设为 `mode=assist` 才参与执行。结果复核还支持 `mode=observe`，仅记录观测而不改变执行结果；默认模式为 `off`。
- **安全保障**：所有敏感密钥采用 Fernet（基于 AES-128-CBC 与 HMAC-SHA256 的认证对称加密）本地加密落盘，前端脱敏展示；多 Worker 环境自动触发单写进程安全告警。

待处理建议会显示在任务日志弹窗的规则建议页签；**日志** 页的详情弹窗仅在存在建议时显示建议面板。应用建议遇到 HTTP 409 时，需基于最新任务配置重新审阅。
